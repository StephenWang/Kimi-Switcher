## 构建中处理的问题

官方 NSIS 下载在 Tauri 内部超时，使用 PowerShell 下载同一官方发布文件，并按 Tauri 上游源码的 SHA1 校验工具归档及插件后填充本机工具缓存；没有关闭校验或使用第三方可执行文件。具体上游依据为 https://github.com/tauri-apps/tauri/blob/dev/crates/tauri-bundler/src/bundle/windows/nsis/mod.rs 。

系统 TEMP 使用 8.3 用户目录别名时，重命名在 Rust/.NET 中均报系统错误 6。测试使用项目内的独立临时目录后通过；应用原子写失败时仍然中止，不降级为覆盖写。

## 实现取舍

- 在原仓库的独立子目录、`codex/kimi-switcher` 分支开发，未创建额外工作树；与其他项目共享父仓库，提交严格限定本项目。
- Windows 下阻止检测到的 CLI 进程，并加文件独占与写入复核；同时新启动 CLI 仍可能需要重新登录。
- 测试临时目录位于项目内，需要项目目录可写。
- 轮换后的令牌先保存，再请求额度，增加一次磁盘操作以避免额度请求失败丢失新令牌。
- 全部账号刷新采用并发数 1，换取活动凭据写入顺序明确；账号较多时刷新较慢。
