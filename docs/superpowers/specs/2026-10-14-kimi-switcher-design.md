# Kimi Code CLI 多账号切换助手设计

日期：2026-10-14

## 目标与范围

实现 Windows 桌面应用，采用 Rust + Tauri 2，界面以用户提供的截图为依据。用户已选择切换默认 Kimi Code CLI 凭据，使普通终端中后续启动的 `kimi` 使用选中的账号。

首版面向本机已安装的 Kimi Code CLI 2.1.1。项目独立放在 `kimi-switcher/`，交付源代码、开发说明和通过构建验证的 Windows 应用。已有 Python 项目不属于修改范围。

支持添加账号、导入当前账号、切换、单个及全部刷新、重命名、删除、深浅色主题。账号卡片显示当前状态、名称、可查询到的套餐、7 天及 5 小时已用比例、重置时间和刷新状态。

## 已验证的集成依据

- 本机 `kimi --version` 返回 `2.1.1`，通过 npm 安装的 `@moonshot-ai/kimi-code` 启动。
- `kimi login --help` 提供设备授权登录，以及 `--region mainland-cn|global`。
- 本机当前数据目录为用户目录下的 `.kimi-code`，其中存在 `config.toml` 和 `credentials/kimi-code.json`。
- 官方配置文档支持 `KIMI_CODE_HOME`，运行时若存在该环境变量则优先使用对应目录。默认目录用于本机正常终端；独立目录用于添加账号时的隔离授权。
- 本机安装包的额度实现请求 coding API 的 `/usages`，解析 `usages.limit_7d`、`usages.limit_5h` 的 `used_ratio` 和 `reset_time`。还可能返回月度额度，首版重点呈现截图中的两个周期。
- 旧 `.kimi` 目录存在迁移标记，首版不把它当成 2.x 的活动凭据来源。

依据：

- https://moonshotai.github.io/kimi-code/en/configuration/config-files.html
- https://github.com/MoonshotAI/kimi-code
- 本机 CLI 的帮助输出及安装包 `dist/main.mjs` 中的 OAuth、managed-usage 实现。

实施时继续核实当前版本的令牌格式、锁协议及套餐字段；这些属于适配器实现验证，不能通过臆造字段或固定套餐名称替代。

## 架构

前端使用 TypeScript + Vite，采用轻量组件组织界面。Tauri IPC 仅传输账号显示信息、状态及操作结果。

Rust 后端分为账号仓库、CLI 适配器、登录任务、额度服务、切换事务和 Tauri 命令层。账号仓库负责加密持久化；CLI 适配器负责数据目录解析、凭据格式、官方登录调用、令牌刷新及当前账号识别；额度服务负责网络查询和响应解析；切换事务负责锁定、同步、备份、替换及回滚。

账号元数据包括随机 ID、名称、创建时间、刷新时间、查询缓存和状态。凭据单独保存，由 Windows DPAPI 以当前 Windows 用户身份加密。前端、普通日志和错误消息不包含 access token、refresh token 或完整凭据文件。

应用操作全局串行化。全部额度刷新采用受限并发；同一账号的刷新与切换互斥。UI 对进行中的操作禁用重复提交并显示进度。

## 导入与当前账号识别

导入读取实际 CLI 数据目录中的当前凭据，验证结构并加密保存。以稳定身份字段识别账号；如接口或凭据不提供稳定身份，使用有说明的凭据关联指纹，不能仅依赖会变化的 access token 认定账号不同。

重复导入已识别账号时更新凭据和状态，不创建重复卡片。无法确定身份时提示用户明确选择更新已有账号或新建，不能静默覆盖。

应用启动及操作前重新读取活动凭据，识别外部 CLI 登录造成的变化。未保存的活动账号显示“当前 CLI 账号尚未导入”。“当前”标记以实际磁盘凭据匹配结果为准，不能只依据上一次点击结果。

## 添加账号

在应用专用临时目录中设置 `KIMI_CODE_HOME`，调用官方 `kimi login`。此流程只进行授权，不发起模型推理。

应用显示授权链接、等待状态和取消操作；通过默认浏览器打开官方授权页面。CLI 启动路径和参数使用参数数组，不能拼接任意 shell 命令。Windows npm 的启动方式通过已检测到的 Node 与入口脚本，或可靠的 CLI 可执行入口适配。

登录成功后验证隔离目录中的凭据，将账号加密保存。原活动账号保持有效，因此“添加”不会悄悄切换当前 CLI 账号。隔离登录生成的 managed provider 配置作为兼容性校验资料；首次启用账号时只补充 CLI 必须的托管配置，保留用户其他模型、工具、权限和服务配置。

登录取消、超时或失败时终止应用启动的子进程，清理临时凭据，不新增无效账号，不修改活动 CLI 凭据。程序退出时同样清理自身登录任务。

## 切换事务

1. 解析并验证当前 CLI 目录与目标账号，不接受前端提供任意文件路径。
2. 获取应用操作锁，并按已核实的 CLI 凭据锁协议协调跨进程写入。锁无法可靠获取时终止切换。
3. 读取当前磁盘凭据；如它属于已保存账号，先加密同步最新令牌，避免用旧 refresh token 覆盖 CLI 已刷新的令牌。
4. 备份将被修改的凭据及必要配置，记录恢复信息。备份含秘密，使用 DPAPI 加密，设置短期保留策略。
5. 校验目标凭据和必要 provider 配置，先在临时文件中准备完整内容，再原子替换活动文件。任何配置补充必须以 TOML 结构编辑保留其他字段。
6. 回读验证后更新当前标记。失败则回滚，并区分“切换失败且已恢复”和“恢复失败，需要处理”。

检测到正在使用同一全局凭据目录的 Kimi CLI 时阻止切换，并提示先关闭相关会话，不强制结束用户进程。无法明确判断关联时展示检测依据并要求用户关闭相关 CLI 后重试。

切换影响随后启动的 CLI。UI 明确提示已启动会话需要退出并重新启动；不能承诺已启动会话立即使用新账号。

启动时检查未完成事务，恢复或显示恢复问题后才开放新的切换操作。

## 令牌与额度刷新

遵循当前 CLI OAuth 协议刷新过期令牌，使用对应地区的官方认证端点。网络请求设置超时，有限重试瞬时网络及 5xx 错误，尊重 429 的等待信息；授权拒绝不无限重试。

活动账号的刷新采用与 CLI 相容的锁，读取最新磁盘令牌，刷新成功后同时更新活动文件和加密仓库。非活动账号刷新只更新加密仓库。刷新失败保留原凭据；明确失效时提示重新登录。

额度数据使用当前 CLI 的 coding API 请求方式和地区配置。只对官方 HTTPS 端点发送令牌；不向未经验证的配置主机发送 OAuth 凭据。套餐信息仅展示经核实的接口字段，缺失时显示“套餐信息暂不可用”。

进度条表示已用百分比，默认以百分比显示。接口若只提供比例，不把 `30/100` 伪装成请求次数。7 天进度条使用绿色，5 小时使用黄色，高使用率使用红色。缺失字段显示“暂无数据”，区别于真实 0%。

重置时间按系统本地时区显示，测试覆盖时区偏移、无效时间和跨日。失败时保留上次成功数据，并标明更新时间及本次错误；无历史数据时显示明确空状态。

## 界面与交互

主窗口标题为“Kimi 换号器”，默认深色，尺寸接近截图且可缩放。顶部包含“添加账号”“导入当前账号”“刷新”“浅色/深色”。账号卡片在窄窗口中允许按钮换行，不截断操作入口。

每张卡片包含序号或绿色当前标记、账号名称、套餐标签、切换/刷新/重命名/删除按钮，以及两行额度进度条和重置时间。

空列表展示添加或导入入口。重命名采用应用内对话框，校验非空、长度及重复名称。删除需要确认，仅删除助手保存的数据；当前 CLI 凭据仍保留，并变为未导入状态。全局错误、每账号错误和操作完成提示分别有明确位置，避免只依赖颜色。

按钮可键盘操作，对话框管理焦点，进度条提供可访问的名称和数值。主题偏好持久化。首版不增加后台自动切换、自动耗尽额度、聊天界面或账号分享。

## 验证与交付标准

- Rust 测试：账号去重、凭据同步、DPAPI 往返、写入失败回滚、未完成事务恢复、运行中阻止切换、锁冲突。
- 使用临时 CLI 目录验证添加、导入、切换和删除，不修改用户真实凭据进行自动化测试。
- 使用脱敏合成响应测试额度比例、缺失数据、时间转换、授权拒绝、限流和网络失败。
- 前端类型检查和生产构建成功，Rust 格式检查、测试及 Tauri 构建成功。
- 桌面或浏览器视觉检查覆盖截图布局、空状态、登录等待、错误状态、浅色主题和窄窗口。
- 真实浏览器授权需要用户完成登录；没有该验证时明确报告“未验证真实新账号授权”，不能把模拟流程说成真实登录成功。
- 文档提供环境要求、开发与构建命令、CLI 版本范围、凭据加密位置、切换作用范围和恢复说明。

## 风险与处理

CLI OAuth、额度和锁协议属于版本耦合点，集中在适配器并标注验证版本。检测到不支持的凭据格式或 CLI 版本时拒绝写入并给出说明。

DPAPI 数据绑定当前 Windows 用户和系统环境，首版不提供跨电脑账号迁移。CLI 自身凭据保持官方格式，助手仓库和备份使用加密存储。

若实现验证发现无法保证兼容锁和可靠原子恢复，必须先收紧切换条件并向用户说明，不降级为无保护覆盖。
